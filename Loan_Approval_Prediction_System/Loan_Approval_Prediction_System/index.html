    ALGORITHM ARCHITECTURE

    Which Machine Learning Algorithms Are Used Here?

    Mathematical formulation, operational logic, and banking credit risk characteristics for each classifier.

    CHAMPION · 98.1% ACC
    🌲🌲

    Random Forest Classifier

    Ensemble Bagging (200 Trees)

    Builds an ensemble of 200 de-correlated decision trees using Bootstrap Aggregation (bagging) and random feature subspace sampling at every split.

    Ensemble Averaging: \hat{P}(Y=1|x) = \frac{1}{B} \sum_{b=1}^{B} P_b(Y=1|x)
    Hyperparameters: n_estimators = 200, max_features = sqrt(p), random_state = 42
    Why it excels: Dampens single-tree variance by 1/B, captures non-linear collateral thresholds without overfitting, and delivers 99.25% approval recall.
    RULE-BASED · 97.3% ACC
    🌳

    Decision Tree (CART)

    Recursive Binary Partitioning

    Constructs a single binary decision tree by recursively partitioning applicant features to minimize Gini Impurity at every branch node.

    Splitting Criterion: I_G(t) = 1 - \sum_{i=1}^C p(i|t)^2
    Banking Suitability: White-box interpretability: allows bank compliance teams to trace exact logical paths (e.g. if CIBIL > 549 and Loan Term ≤ 10).
    LINEAR BASELINE · 92.3% ACC
    📈

    Logistic Regression

    Parametric Linear Model

    Models the log-odds of loan approval as a linear combination of standardized numeric inputs and one-hot encoded categories, transformed through the standard logistic (sigmoid) function.

    Sigmoid Link: P(Y=1|X) = \frac{1}{1 + e^{-(\beta_0 + \mathbf{w}^T \mathbf{x})}}
    Banking Role: Regulatory benchmark for credit scorecards; provides direct log-odds interpretations and calibrated probabilities (ROC-AUC: 97.5%).

    Comparative Analysis Across Banking Criteria

    Dimension Logistic Regression Decision Tree (CART) Random Forest (Ensemble)
    Decision Boundary Linear hyperplane in transformed space Axis-parallel orthogonal rectangles Smooth non-linear ensemble boundary

    DATA INTEGRITY & ETHICAL AI

    Methodology, Pipeline & Limitations

    How data integrity is preserved and how this project relates to UN Sustainable Development Goals.

    01

    Safe Preprocessing Pipelines

    Uses scikit-learn ColumnTransformer to prevent data leakage. Missing values are imputed using training medians and modes; categories are one-hot encoded.

    02

    Stratified Validation

    Maintains exact class proportions (Approved vs Rejected) across both training (3,415) and testing (854) subsets with a fixed random seed (42).

    03

    Dual Architecture

    Supports both Python Flask REST API persistence with MySQL/SQLite and instant offline client-side evaluation without server dependencies.

    04

    Responsible AI & SDGs

    Connects equitable capital allocation to UN Sustainable Development Goals: SDG 1 (No Poverty) and SDG 8 (Decent Work & Economic Growth).

    05

    Dataset Limitations

    Historical training data may reflect past institutional biases. Algorithmic outputs are statistical demonstrations and not a legal lending decision.

    06

    Security & Privacy

    Passwords are hashed using Werkzeug PBKDF2:SHA-256. User application histories are strictly isolated with parameterized SQL queries.
